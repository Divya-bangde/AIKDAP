## Implementation

- **V13:** `InteractiveEquationCard.tsx` now subscribes to the existing theme observer for both single/system calculators. Curve/reference/current colors update without remounting input state or resetting reference snapshots/widen-only ranges.
- **V13 final review correction:** native Plotly receives a semantic `uirevision` based on axis titles/types/declared ranges/domains, trace identities/types, and explicit calculator Fit tokens. Theme and value-only updates retain the interaction key so manual 2D zoom/3D camera state can survive; unit/axis/identity/Fit changes deliberately reset it. Utility regressions cover preserved and changed keys; root verifies actual browser interaction state.
- **Actual 3D browser follow-up:** Diana demonstrated that Plotly 4 still reset an orbited camera despite stable global uirevision, and that mixing 2D axis updates into a pure-3D relayout raised `_inputDomain`. The native renderer now carries only public `graphDiv.layout` interaction fields (camera/aspect/ranges) into a newly themed layout when semantic revision is unchanged, and sets scene uirevision explicitly. Pure-3D Fit/Reset sends only scene fields. `npm test -- src/features/research/PlotlyVisualization.test.tsx src/features/research/plotly-view.test.ts --maxWorkers=2`: **8 passed / 2 files, exit 0, 3.64s**. Root/Diana must rerun the actual browser diagnostic after rebuilding; these tests alone are not proof of 3D camera behavior.
- **V14:** `RendererBoundary.tsx` contains lazy/render errors locally and recreates a rejected lazy component on its one explicit retry. Research, analytics, equations, experiment charts and paper-map canvas use local guards. Calculator source/variables remain inspectable if its module fails.
- **V14 / P04:** native `Plotly.react` replaces the generic React factory and window resize listener. Updates are queued; load/draw failures are caught; retries are bounded per spec/attempt. The local ResizeObserver ignores hidden/detached targets and contains synchronous/asynchronous failures. Pending work is purged after unmount. Memoized frame selection and spec/attempt failure guards prevent table disclosures from implicitly retrying failed loads.
- **V14:** Plotly's generic modebar is disabled. Explicit Fit/reset controls preserve supplied reset ranges; frame series selection controls all rendered/table/exported traces. Existing equation Fit/input/reference behavior remains.
- **V14 final 3D control review:** Fit now clears explicit ranges/enables autorange on all three scene axes, while Reset restores each supplied scene range (or automatic bounds when absent), as well as the default camera. A native relayout-call regression verifies both actions on x/y/z. `npm test -- src/features/research/PlotlyVisualization.test.tsx src/features/research/plotly-view.test.ts --maxWorkers=2`: **7 passed / 2 files, exit 0, 4.45s**.
- **V14 exports:** the frame downloads current selected data/context as JSON and chart/diagram SVG with visible title, finding, units, origin, source/scope qualifiers and embedded exact metadata. Added context uses DOM textContent, so untrusted labels remain inert. Image export requires matching completed render spec/revision before/after image generation, preventing stale-image/new-metadata pairs. Errors preserve data/source alternatives. Selected proof indexes are remapped to exported trace indexes and original received indexes are retained explicitly.
- **V14 / P03:** Mermaid asynchronous/synchronous initialization/render failures produce an explanation, raw source and a single retry; stale SVG is cleared. Source budgets are 20,000 characters, 500 lines and 300 recognized relationships, with Mermaid's own maxTextSize/maxEdges constraints. Parser error artifacts with the renderer's own temporary ID are removed. Strict security remains enabled.
- **P01:** exact `plotly.js@4.0.0` core/scatter + bar/pie/heatmap/contour form the ordinary lazy bundle; scatter3d/surface register only through a separate lazy module. `visualization-registry.ts` centralizes supported types/dimension selection and rejects unsafe/duplicate IDs before selectors reach Plotly. Unsupported types have an actionable local failure rather than silent substitution.
- **P02:** `mathjs/number` narrows the evaluator dependency while retaining the complete existing AST allowlist and finite-domain safeguards. Mermaid remains fully featured/lazy because a tiny build would remove supported diagram grammars. Removed unused direct plotly.js-dist-min/react-plotly.js and corresponding old type dependencies after verifying no source references remained.

Configuration/registry/limits/recovery notes: `docs/visualization-rendering.md`.

## Final P03 trend display reduction

Root's final scope check required an appropriate large-series display policy in addition to bounded rejection. `trend-reduction.ts` now samples only validated, explicitly numeric/date analytics trend traces above 1,000 points, within the existing accepted 10,000-per-trace/50,000-total budget. Contiguous valid-segment buckets retain original min/max points; mandatory first/last points, global extrema, both null-run boundaries and adjacent segment endpoints remain. Original chronological index order is preserved, no averaging occurs, and groups/metrics/gaps never share a bucket. If gap complexity cannot fit the display target, the full accepted trace remains with an explicit reason. Bars, pies, trajectories, ordinal and unspecified lines stay unchanged.

Per-UID metadata records original/display counts, method, bucket width, retained sorted-trace indexes and received-result row indexes. Visible notices state the transformation. Plot-aligned tables/exports still use exact selected points; a separate full received result JSON download retains every original received row, plan, scope/precision metadata and display transformations. It never claims to recover rows omitted by a server cap.
